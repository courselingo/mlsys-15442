# 配图复核的实测裁定

> **用途与规则**：同 `courselingo/docs/quality-audit.md` **附录八 / 附录十一 / 附录三十八**。
> 一条复核结论**被实测证伪**、或**指不出任何房规**时，把裁定留在这里，
> `check_reviewed.py` 会读到它并覆盖该条。
>
> **`依据` 一栏必须含实测值**（可被任何人独立重测）。写「我认为它是对的」不作数。
>
> **★ 判定的门槛（2026-09-29 起，已写进复核提示词）**：判「需小修」必须指认它违反了下面
> **R1–R7** 中的哪一条，并给出「规则要求的量」与「你在图上量到的量」。
> **指不出规则的口味性主张（不对称、不居中、节奏不均）不构成「需小修」。**
>
> ```
> R1  块间距 ≥ 25px            R2  框高 = 字号 × 3
> R3  框内文字光学居中 = 框中心 + 字号 × 0.35
> R4  画布边距 20–25px          R5  不重叠；文字右缘 + 10px < 右侧邻居左缘
> R6  不允许斜的直线段          R7  调色板与字体栈
> ```
>
> **已知边界**（实测）：守卫只查「依据含数字」。
> 它挡得住「没有实测值」，**挡不住「有数字但没真量」** ——
> 真正的保护是：① 文件可被审计；② 引的数字可被独立重测；③ 它是留档而非一次性判断。

## 逐条说明

### `introduction-to-mlsys-7` / `-12` / `-15` · 「右端未齐 / 右边缘不齐」（同一形状的三条）

**这三条是**真的**（我逐张量过，它给的数字基本准确），而它们**不违反任何一条房规**。**

```
它报的现象：一张图里「通栏横幅」的右缘 与「卡片行」的右缘 不同
  -7   737 vs 756（差 19）
  -12  711 vs 733（差 22）
  -15  737 vs 745（差  8）
它引的规则：无（三条都只描述了不对齐，没有引 R1–R7 里的任何一条）
```

**⇒ 而房规算的是**整张图最外缘**的边距（`viewbox-clipping.mjs`：`MARGIN_MIN=20 / MARGIN_MAX=25`，
按最外缘内容算），三张的最外缘分别是 756 / 733 / 745 ⇒ 右边距 **23 / 23 / 21** ⇒ **全部合格**。
`svg-lint --strict` 三张各 **0E/0W**。**

**★ 所以裁定是「可用」，而这不是「它错了」** —— 是**它的主张落在门槛之外**：
门槛要求「指认违反了哪一条房规」，而这三条**指不出**。

**★★ 而这里我要写清一件事：这个门槛**不是为了让它闭嘴**。**
它这三条报的是**真实的排版不一致**（横幅比卡片行短 19/22/8px），而那确实多半是疏忽。
**⇒ 所以我把它们**另函告知作者**，但**不据此拦路** ——
因为「需小修」这个判定的语义是「**有规则被违反，必须改**」，而不是「**可以更好**」。

**★ 而这一条暴露了流程缺一档：**观察**。**
```
闸门只接受三档：可用 / 需小修 / 有错误
⇒ 而「注意到了，但它不违规、只是可以更好」这一档**没有地方放**
⇒ 目前的办法：裁定为「可用」，并在本文件与给作者的信里留下那段实测
⇒ **建议**（未定）：给复核报告加第四档「观察」，让闸门忽略它、而作者能看到它
```
